## What checked out

- **IDOR:** every user query in `db/queries/{care,checkups,fertility,pregnancy/v2_*}` filters on `user_id`
  (catalog reads use `user_id IS NULL OR user_id = ?`). Every by-id handler loads through a query scoped to the
  user and returns 404 on a miss. Checkups admin queries are limited to `user_id IS NULL`, so admins never see
  users' custom checkups. Integration tests cover isolation per domain.
- **Admin:** all new admin routes go through `httpadmin.Handle` with `kit.Admin`. Static paths are registered
  before param paths.
- **Time:** handlers take `clock` → `.In(civildate.Tehran)`. Dates go through `civildate`, with no
  `time.Now()` in logic. The seed `CONVERT_TZ(UTC_TIMESTAMP(),'+00:00','+03:30')` is correct: Iran has no DST
  since 2022. The Jalali port (`checkups/engine/jalali.go`) matches jalaali-js, including the pre-Nowruz
  `leap` branch and `FromJalali`.
- **Migrations:** 00002–00005 have Laravel twins (`backend/database/migrations/2026_09_2{3,4,5,6}_*`). They use
  `IF NOT EXISTS` and `INSERT IGNORE` on unique keys, and have reversible Downs. 00006 is data only, guarded by
  a byte comparison, and reversible.
- **Multi-row writes:** custom checkup + seed record, fertility day (fertility_logs + daily_health_logs) and
  admin reorder/alert-rule writes each run in one transaction. The care-item and checkup-type delete guards are
  single atomic statements.
