# راهنمای فایل طراحی Figma — `ritme.fig`

> این فایل مرجعِ «چی کجاست» برای فایل طراحی محصول است. هدفش این است که هر وقت
> خواستی از روی طرح کد بزنی، بدون باز کردن Figma بدانی هر بخش چه چیزی دارد و
> مخصوصاً بخش **Main Pages** (بخشی که واقعاً باهاش کار می‌کنیم) دقیقاً شامل چه
> صفحاتی است.

---

## ۱. این فایل چیست؟

`ritme.fig` خروجی خام فایل طراحی Figma با نام **«Ritme»** است (نه یک تصویر، بلکه
کل سند طراحی). از نظر فنی یک آرشیو ZIP است که داخلش:

| بخش | محتوا |
| --- | --- |
| `canvas.fig` | خودِ سند طراحی به‌صورت باینری (فرمت داخلی `fig-kiwi`) — طرح، لایه‌ها، متن‌ها |
| `images/` | همهٔ تصاویر/آیکون‌های استفاده‌شده در طرح |
| `thumbnail.png` | پیش‌نمایش کوچک |
| `meta.json` | متادیتا (نام فایل «Ritme»، تاریخ خروجی) |

> نکته: این یک فایل باینری است و مستقیم قابل‌ویرایش با کد نیست. برای دیدن جزئیات
> بصری باید در خودِ Figma بازش کنی. این سند فقط نقشهٔ محتوایش است تا سریع بدانی
> هر چیزی کجاست.

### ساختار کلی سند

سند از چند **Canvas** (همان تب‌های بالای Figma، اینجا به آن‌ها «صفحه/Page» هم
می‌گوییم) تشکیل شده. در مجموع **۱۴ کانواس** وجود دارد:

| Canvas | چیست |
| --- | --- |
| `Internal Only Canvas` | یادداشت‌ها و چیزهای داخلی تیم |
| `Mood board` | فضاسازی و الهام بصری |
| `Idea` | ایده‌های اولیه |
| `Use` | — |
| `Color pallet` | پالت رنگ محصول |
| `Appstore download BTNS` | دکمه‌های دانلود از استور |
| `iPhone Mockups` | ماکاپ گوشی برای پرزنت |
| `App Wireframe` | وایرفریم‌های اولیهٔ اپ |
| `Design in shad+` | آزمایش‌ها با کامپوننت‌های shadcn |
| `AUTH` | فلوی احراز هویت (ورود/ثبت‌نام/کد یک‌بارمصرف) |
| `empty` | خالی |
| `Yasins doc` | مستند شخصی |
| **`Designs`** | **کانواس اصلی طراحی نهایی — بخش مورد نظر ما اینجاست** ⬅️ |
| `Yard` | محل کار/آزمایش پراکنده |

**فقط با کانواس `Designs` کار داریم** — بقیه بایگانی/الهام/آزمایش هستند.

---

## ۲. بخش مورد نظر ما: **Main Pages**

### کجاست؟

مسیر دقیقش در سند:

```
Document
└── Canvas: «Designs»
    └── Section: «Flow»
        └── Section: «Main Pages»   ⬅️ اینجا
            └── صفحه‌های اصلی اپ
```

یعنی داخل کانواس `Designs`، یک سکشن بزرگ به اسم `Flow` هست و داخل آن سکشن
`Main Pages` قرار دارد. کنار همین بخش، طراح یک یادداشت گذاشته:
**«این صفحات رو میخوایم»** — یعنی این‌ها همان صفحاتی‌اند که قرار است ساخته شوند.
پس تمرکز درست است.

### چه صفحاتی داخلش هست؟

بخش `Main Pages` شامل **۴ صفحهٔ اصلی متمایز** است (بعضی‌ها با چند حالت/نسخهٔ کنار
هم برای نمایش state‌های مختلف طراحی شده‌اند):

---

#### 🏠 ۱. صفحهٔ خانه — `Homepage v3`

داشبورد اصلی اپ در حالت **چرخهٔ قاعدگی (Cycle mode)**. پرمحتواترین صفحه. شامل:

- **نوار وضعیت چرخه** با تاریخ‌های شمسی: `۱۵ آذر`، «پنجرهٔ باروری»، `۲۰ آذر`،
  «تخمک‌گذاری»، `۳۰ آذر`
- شمارشگر **«پریــــود بعدی در …»**
- کارت **«توصیه‌های امروز»** (`DailyRecommendations`)
- **«وظایف امروز»** با نوار پیشرفت (`۲/۴`، «۵۰ درصد»، «پیشرفت امروز»)
- **«چالش امروز»** — «این هفته روند خوبی داشتی! به همین منوال ادامه بده»
- کارت **«نکتهٔ هوشمند»** با متن آموزشی درباره فاز لوتئال و تغذیه + لینک «مشاهده کامل»
- **«خلاصه هفته»** / **«وضعیت امروز»** (بر اساس سیکل فعلی)
- بخش **«سیکل‌های من»**: «سیکل فعلی: روز ۱»، «شروع شده در ۱۹ اکتبر»،
  «ثبت سیکل‌های قبلی»، «خلاصهٔ سیکل»
- کامپوننت‌های تکرارشونده: `Status Bar`, `Header`, `TodayCalender`, `InsightPreview`,
  `Statistics`, `DidYouKnow`, و **`Navigation`** (نوار پایین)

> نگاشت به کد: این می‌شود صفحهٔ `pages/home` + ویجت‌های `insights-panel`،
> `cycle-calendar` (بخش TodayCalender) و کارت‌های `entities/article`.

---

#### 🔄 ۲. صفحهٔ چرخه — `Cycle`

نمای خلاصهٔ وضعیت چرخهٔ قاعدگی. شامل:

- `Status Bar` + `Header`
- کارت **`CycleSummaryCard`**: «بر اساس سیکل فعلی شما»
- **«سیکل‌های من»** → «سیکل فعلی: روز ۱»، «شروع شده در ۱۹ اکتبر»
- «ثبت سیکل‌های قبلی»، «خلاصهٔ سیکل»
- چند بلوک کارت با دکمه (`Frame 36/38/39` + `Button`)

> نگاشت به کد: `pages/…` مربوط به تب چرخه + `entities/cycle` (محاسبات فاز/روز سیکل).

---

#### 📅 ۳. صفحهٔ تقویم — `Calendar` (دو نسخه کنار هم)

تقویم شمسی برای دیدن و ثبت روزهای چرخه. شامل:

- سوییچ **«ماه کامل»** و عنوان ماه شمسی: **`دی ۱۴۰۳`** + دکمهٔ «ویرایش»
- **`WeeklyCalendar`** (تقویم هفتگی) + گرید ماهانه
- انتخاب روز: «۱۹ فروردین»، «سیکل روز ۴»، «احتمال باردار بودن −»
- متن آموزشی فاز لوتئال (همان کارت نکتهٔ هوشمند)
- در نسخهٔ دوم: **باتم‌شیت ثبت حال** — «امروز چه حس و حالی دارید؟ / علائم و خلق و خو
  و … را ثبت کنید» و یک `pickers` (انتخابگر تاریخ/ماه)
- کامپوننت `Navigation` پایین

> نگاشت به کد: ویجت `cycle-calendar` + `pages/calendar`. حتماً همهٔ تاریخ‌ها از
> لایهٔ `shared/lib/date` (شمسی) بیایند — این صفحه پر از تاریخ است.

---

#### ➕ ۴. صفحهٔ ثبت — `Add Log` (چند نسخه/باتم‌شیت)

فلوی **ثبت اطلاعات روزانه**. به‌صورت چند فریمِ باتم‌شیت طراحی شده که هر کدام یک
نوع ثبت را نشان می‌دهند (مرحله‌به‌مرحله). حالت‌هایی که در طرح دیده می‌شود:

- ثبت **دما**ی بدن (واحد `°C`) — مرتبط با ردیابی BBT
- ثبت **وزن** (واحد `kg`)
- ثبت **علائم/خلق‌وخو** (فریم‌های مرحله‌ای `Frame 2147226157…161`، بخش‌های
  `Explanation` و `Degree` برای انتخاب شدت)
- هر شیت با `Up`/`Down` (دستهٔ کشیدن) و یک `Button` تأیید بسته می‌شود

> نکته: چون این‌ها overlay/bottom-sheet روی صفحات دیگرند، خودِ متنِ لیبل‌ها داخل
> کامپوننت‌های master قرار دارد و در طرح روی این فریم‌ها مستقیم دیده نمی‌شود.

> نگاشت به کد: فیچرهای `features/log-symptom` و `features/log-period` +
> `entities/symptom`. UIِ شیت در `widgets/symptom-tracker`.

---

## ۳. جمع‌بندی نگاشت طرح ↔ کد

| صفحهٔ Figma (Main Pages) | لایهٔ FSD پیشنهادی | تب نوار پایین |
| --- | --- | --- |
| `Homepage v3` | `pages/home` + `widgets/insights-panel` | خانه |
| `Calendar` | `pages/calendar` + `widgets/cycle-calendar` | تقویم |
| `Cycle` | صفحهٔ تب چرخه + `entities/cycle` | چرخه/بینش |
| `Add Log` | `features/log-symptom` + `widgets/symptom-tracker` | دکمهٔ + وسط نوار |

نکات مهم هنگام پیاده‌سازی از روی این طرح:

1. همهٔ تاریخ‌های نمایشی در طرح **شمسی** هستند (`دی ۱۴۰۳`, `۱۹ فروردین`) → فقط از
   `shared/lib/date`.
2. همهٔ اعداد با **رقم فارسی** طراحی شده‌اند → در لایهٔ فرمت/`next-intl` هندل شود،
   نه دستی در کامپوننت.
3. جهت **RTL** است → استایل‌ها منطقی (`ms-`, `pe-`, `text-start`).
4. متن‌های محتوایی (مثل «نکتهٔ هوشمند») محتوای سلامت‌اند → طبق §۱۱ راهنمای پروژه،
   نباید حالت تشخیص/تجویز پزشکی داشته باشند.

## ۴. اگر خواستی دوباره محتوای فایل را استخراج کنی

فایل `canvas.fig` این ساختار را دارد: هدر `fig-kiwi`، بعد یک uint32 نامعلوم، بعد
`uint32` طولِ اسکیمای فشرده (**raw deflate**)، و سپس بلوک دادهٔ اصلی که با
**zstd** فشرده شده و با اسکیمای Kiwi باید decode شود. اسکریپت‌های استخراج در
پوشهٔ scratchpad این سشن ساخته شدند (decode اسکیما → decode پیام → پیمایش درخت
`nodeChanges` برای گرفتن نام فریم‌ها، والد، و متن `textData.characters`).
